## Distinctive moments

1. **The wrong-URL bug only surfaced in real-data smoke.** All 8 redesign
   tasks landed with green tests including nav-link assertions, because
   every test asserted the same wrong URL my T9.1 spec had written. The
   route prefix mismatch was invisible until I `curl`-ed all 11 routes
   end-to-end. Lesson reinforced: structural tests are necessary but
   not sufficient; full-route smoke catches what unit-level assertions
   designed against the same flawed spec cannot.

2. **The two-file production data layout bug in T9.2.** The dispatch
   log lives in two places — typed events in `.maestro/logs/dispatch.jsonl`,
   cost rows in `docs/data/dispatch-log.jsonl`. T9.2's spec told the
   coder to read both from `resolve_log_path()`, which is wrong. Caught
   by running the endpoint against the real on-disk files after the
   tests passed. The synthetic happy-path test had written events to
   the same file the test patched `resolve_log_path` to point at —
   masking the conflict. Lesson: when synthesizing test fixtures,
   replicate the actual production layout (multiple files, distinct
   shapes), not the simplest single-file model.

3. **T9.4's empty-output coder retry.** First T9.4 coder dispatch returned
   97s of wall and 5535 tokens with no body text — just the banner line.
   Re-dispatched the same spec verbatim; second run returned complete
   3-file output in 56s. No protocol-level retry exists yet; orchestrator
   manually re-dispatches on empty. Tracked as a future-Epic improvement.

4. **The `<style>` exception pattern crystallized.** Three pages (wizard,
   live, problems, plus history after the T9.8 fix) needed page-specific
   CSS for components not shared with anything else — wizard-progress
   dots, the live-view legacy card classes, the problem-row variants,
   the history drill-down. Each landed as ONE `<style>` block in
   `extra_head`, justified by a comment citing design doc §5.3. The
   alternative (adding ~30 single-use classes to `maestro.css`) was
   rejected.

5. **Over-escaped Jinja in T9.7.** Coder output wrapped each Jinja
   directive in `{{ "{% extends ... %}" }}` — a double-rendering hazard.
   Orchestrator wrote the file directly from the spec instead of using
   the coder's literal output. The eventual reviewer passed because it
   reviewed the spec-correct content, not the coder's escaped form.

6. **One reviewer fail across 8 page tasks.** T9.8 was the only fail
   verdict; the fix took ~1 min of edit + 21s of re-review. Eight tasks
   landed without major rework — a good sign that the design doc + base
   template were stable enough for parallel coder dispatch.
