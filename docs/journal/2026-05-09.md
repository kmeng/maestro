**Decided**

- **Worker fleet expansion is v0.0.3 scope, not deferred**. Epic 5
  (worker fleet expansion: librarian, reviewer, scribe + rename) folded
  into v0.0.3 mid-implementation rather than pushed to v0.0.4. Rationale:
  the librarian role pays for itself across the remaining 32 v0.0.3
  implementation tasks (each begins with whole-doc reading). The
  meta-pattern: dogfooding's first task surfaced a real cost problem;
  the right response is to build the role that solves it now, not after
  v0.0.3 ships.

- **Role naming convention** (ADR-0008): team-member-style nouns
  (`coder`, `librarian`, `reviewer`, `scribe`); no `cheap_` prefix; no
  model in the name; single token preferred. The fleet reads as a team
  roster, not a function library.

- **I/O contract conventions** (ADR-0008): structured input + output
  per role; every output carries a `concerns` channel for worker
  self-doubt; output validators run before return; verbatim-contract
  fields are server-side-verified, not just system-prompt-trusted.

- **Worker file access** (ADR-0008 + librarian implementation): workers
  MAY read files directly when input would otherwise force the
  orchestrator to load it into its expensive context. Load-bearing for
  librarian's economics — without this principle, the role would
  defeat its own purpose.

- **Shadow mode rollout**: workflow contract recorded in user memory
  (`feedback_shadow_mode_active.md`, to be created in T5.2). Membership
  in the file determines whether the orchestrator runs its own version
  in parallel and presents both to the user. Promotion is by explicit
  user signal; no numeric threshold.

- **`coder` model bump to `deepseek-v4-pro`** (resolves OPEN-5.6).
  Rationale: keeping coder on the legacy `deepseek-coder` model would
  force every future prompt-tuning decision to track two model
  lineages. The v4 lineup is the project's forward direction.
  `MODEL_PRO` and `MODEL_FLASH` constants live in
  `bootstrap/maestro_server.py`, env-overridable via
  `MAESTRO_MODEL_PRO` / `MAESTRO_MODEL_FLASH`.

- **Verification > unit tests for contract checking**. Phase 1 of T5.1
  passed 26 unit tests (mocked client) but failed real-world contract
  verification 50%. Mocked tests cannot exercise the actual model's
  fidelity to a verbatim contract — only a real call can. Lesson
  recorded: any future role with a contract whose enforcement depends
  on model behavior MUST include a real-world smoke step in its
  acceptance criteria, not just unit tests.

- **Tasks close when verification passes, not when code lands**. The
  user explicitly noted: "我认为任务完成了，就可以关闭相关的任务了"
  but the corollary is verification before closing. T5.1's first close
  was premature (before real-world verification); reopening was the
  right call.

**Process learnings**

- **Cost analysis surfaces product, not just optimization**. Mid-session
  the user asked why today's token spend was high. The honest answer
  ("reading whole design docs, plus protocol overhead, plus per-turn
  fixed cost") could have ended at "let me write tighter responses."
  Instead it became: which of these workloads can a cheap worker
  do? — which became Epic 5. The same principle the project is
  built on (dispatch execution-heavy work to cheap models) applies to
  the orchestrator's own work, recursively. This is the project
  finding itself.

- **Real-world verification is not optional for contract roles**. T5.1's
  first close was wrong: 26 unit tests passed but the verbatim contract
  failed 50% on first real use. The lesson is structural — any role
  whose contract depends on model behavior (verbatim, JSON-schema
  adherence, formatting) cannot be unit-tested into compliance.
  Acceptance criteria must include a real call.

- **The verifier is the contract; the prompt is the expectation**.
  When the librarian system prompt was tightened with explicit
  anti-examples, v4-flash *still* produced 60% non-verbatim quotes
  on prose passages. The system prompt influences the worker; it
  doesn't bind it. Code-level enforcement does. ADR-0008 now codifies
  this: any field with a verbatim contract MUST have its handler
  verify before returning.

- **Re-opening is the right move when verification fails**. The user's
  framing: closing requires verification, not just code-landing. The
  flow `close → verify → reopen on failure → fix → re-verify → close`
  is honest about what "done" means. Worth more than a CI-gating
  ceremony.

- **AI-fleet expansion from observed costs > AI-fleet expansion from
  speculation**. Epic 5's three roles weren't picked off a feature
  list; each was traced to a specific consumption pattern in T0.1's
  session log. `librarian` ↔ "reading whole design docs"; `reviewer`
  ↔ "evaluating worker code line-by-line"; `scribe` ↔ "drafting commit
  messages from a known diff." The discipline: only build a role when
  its consumption pattern has been observed with the orchestrator's
  own time. Otherwise the role's value is hypothetical.

- **Documentation cost was again decisive on flexibility**. Mid-session
  decisions (Epic 5 introduction; coder model bump; verbatim
  hardening) all required updating documents that had already been
  written and approved. Each change cost minutes because the docs
  exist; in a code-only world the same change would have required
  retracing through scattered implicit knowledge. The
  documentation-as-throughput-multiplier reframe (yesterday's project
  memory entry) keeps holding empirically.
