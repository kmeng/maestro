## Distinctive moments

### 1. T10.1 took 3 coder dispatches before clean

Pattern of failure cascade:
- **Dispatch 1** (154s, 9.7k tokens): 10 deliverables produced per spec.
  Two spec-design bugs surfaced at test-run time:
  - `argparse.REMAINDER` does not forward `--port`-style options
    through subparsers in Python 3.9+ (REMAINDER captures positional
    tail; parent parser still tries to interpret `--` tokens first).
  - Used `importlib.metadata.version("maestro")` as version source —
    returns the **installed** version (0.0.3 from prior editable
    install), not the source `__version__` (0.0.4 from this PR).
    Diverges when local source is ahead of installed metadata.
- **Dispatch 2** (43s, 3.4k tokens): corrected both via
  `parse_known_args` + `__version__`-first lookup. Tests went 5/7 →
  7/7 in the CLI suite.
- **Dispatch 3** (50s, 3.7k tokens): file relocation caused cascade —
  6 test files used `importlib.util.spec_from_file_location` pointing
  at the old `bootstrap/maestro_server.py` path, but my new
  deprecation shim at that path **executed run_stdio() at import
  time** (no `if __name__ == "__main__"` guard). Tests went 558 →
  fail (139 errors). Fixed via: (a) shim's print + serve guarded by
  `__name__ == "__main__"`, (b) test fixtures repointed to
  `maestro/mcp_server.py`. Three files fixed by coder + 3 by sed
  hand-author (per `feedback_dogfooding_implementation` exception:
  surface + pivot for sed-equivalent path-string replacement).

Lesson: **task decomposition audit (per `feedback_task_decomposition_audit_at_start`)
must include "what test files import-load the file under move?"** I
ran the 4-point checklist (file mutex / upstream API contract / no
pending-fix cascade / conftest compat) but missed the import-loader
cascade. New audit item: any file move requires grep for
`spec_from_file_location` + direct package imports.

### 2. Reviewer payload quality matters

T10.2 reviewer returned `fail` with 3 high findings. **2 of 3 were
false** — caused by my reviewer payload using summary placeholders
(`# Covers: ...` for the docs file, `# +line` for the .gitignore diff)
instead of verbatim file content. Reviewer correctly read what I sent;
what I sent was wrong.

Lesson: when sending reviewer the "code" parameter, paste verbatim
file contents, not narrative summaries. Saves a re-dispatch round.

Already encoded in `feedback_worker_payload_completeness.md` for coder
specs — but the rule applies equally to reviewer. Worth adding a
sentence to that memory: "Reviewer's `code` parameter follows the same
verbatim rule — summarized representations cause false-fail verdicts."

### 3. macOS realpath bug caught by smoke (not by tests)

T10.6 smoke first run failed at step 6 with:
```
FAIL: mcp.json command '/private/var/folders/.../maestro' !=
      binary absolute path '/var/folders/.../maestro'
```

`Path.resolve()` in maestro/cli/install.py canonicalises symlinks
(macOS `/var` → `/private/var`). The smoke script computed the
expected path via `os.path.abspath` which does NOT resolve symlinks.
Comparison failed.

This is exactly the kind of platform-specific path mismatch that unit
tests with `tmp_path` would not catch (pytest's tmp_path lands in
the real `/private/var` already; the symlink dance only appears via
`mktemp -d` in shell). The smoke caught a **real** production-equivalent
bug, not just exercised the script. Fix: smoke script switched to
`os.path.realpath`.

The same bug would have surfaced on macos-latest CI runners on first
real release — would have made v0.1.0 ship with a red verify leg
even though the binary worked correctly. Caught a day early.

## Lessons learned (carry-forward)

1. **Importance > size for task selection** (existing memory) was load-
   bearing today. A.3 looked small ("smoke script"); investigation
   surfaced the README-is-aspirational gap; correct response was to
   ship the full Epic 10, not patch the smoke. The user's explicit
   reframe ("pip 不可行...参照 cc-switch") was the key pivot.

2. **Wave coupling needs explicit detection at decomposition time.**
   T10.2 and T10.4 were declared parallel (file-disjoint) but had a
   **runtime dependency** (T10.2's verification step needs T10.4's
   flag). Detected only at apply time; resolved by deferring T10.2
   merge until after T10.4. Future-rule candidate: at audit step,
   also check "does any task's verification step exercise a
   subcommand / API another in-flight task is implementing?"

3. **Reviewer's `code` payload is the same verbatim rule as coder's
   `spec` payload.** Confirmed by T10.2 reviewer returning 2 false-
   positives from my summary-style payload. Will append to
   `feedback_worker_payload_completeness.md` in next memory pass.

4. **Smoke tests against built artifacts catch what unit tests can't.**
   T10.6 caught the macOS `/var` vs `/private/var` symlink mismatch
   that no unit test (under pytest with `tmp_path`) would surface.
   Pattern: production-equivalent smoke is non-redundant with unit
   tests on path-handling code.

5. **PyInstaller hidden-imports inventory is non-trivial but learnable.**
   Coder's first pass missed `uvicorn.protocols.websockets.websockets_impl`
   (newer uvicorn path). Local build still worked because Maestro's
   webui doesn't use websockets (SSE only). Defensive add kept it
   in for future-proofing.

6. **Single-binary release is a UX cliff drop.** v0.0.3 onboarding was
   "git clone + venv + .env + claude mcp add"; v0.1.0 is "download +
   maestro install + restart Claude Code". This is the kind of thing
   the project's existence statement claims (`AI for AI software team`)
   but until today required a developer to even try. Now a curious
   non-developer with Claude Code can install in under 60 seconds.
