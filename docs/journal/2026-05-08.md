**Process learnings**

- "Bug or wrong architecture?" is the most useful question when a fix needs documentation to make it palatable. The v0.0.1 → v0.0.2 transition turned on this question (issue #5 reframe → issue #6 design). Today's work didn't hit it again — but the rule held in the smaller "do we add `httpx[socks]` to requirements.txt?" decision (we said no — it's user environment, not project scope).
- **Per-action approval for state-changing remote operations is worth the latency**. Every `gh issue create` / `gh pr create` / `git push` today went through a draft → review → approval cycle. It cost minutes; it would have cost hours of cleanup if any of the artifacts had been wrong on first publish. The cycle is now codified in project memory.
- **Constitutional changes are worth the ceremony, not despite it**. The maintainer's own framing: "宪法修改应该慎重，但是该修改时也要当机立断." Today demonstrated both halves: ceremony (proper issue + design + approval) AND decisiveness (didn't defer the CLAUDE.md update to a later release for "safety"; did it now because the gap was real).
