**Process learnings**

- **Three back-to-back pass-2 rounds + governance amendment + 33-issue migration in one session worked** — past where decision quality usually tails off — because the design pattern was repetitive across epics (5–6 decisions per round, similar shape), the maintainer pushed back precisely when something was wrong (Epic 0 共进程 framing; D6 language requirement), and each pass-2 had a natural close (status flip + sub-branch merge).
- **Late requirements are cheap to fold in when docs are the canonical truth source.** D6 (Chinese language) surfaced after Epic 1 D5 was approved; folded across vision doc + Epic 0 doc + Epic 1 doc in one commit because no code had landed. This is the AI-doc-economics thesis observable in real time: change cost is a function of artifact mutability, not artifact count.
- **"Verify before batching" pays off small.** First sub-issue creation attempt failed with HTTP 422 (`gh api -f` sends strings; needed `-F`). Test-on-T0.1-first plan caught it before 33 unlinked issues had to be cleaned up. The fix was one character in the script.
- **The maintainer's reframe of "over-documentation" is itself a project artifact** worth preserving: 过度文档化是误读 — it conflates two things (implementation-design disconnect, slow human writing). With AI generation, both go away, and rich documentation becomes a throughput multiplier rather than a bureaucratic tax. This is now baked into the project's workflow via the Implementation-start protocol — the protocol is *only justifiable* under this economic framing.
- **v0.0.3 is the first release where the project's design pass produced more durable artifacts than code (so far)**. The 7 ADRs + 5 design docs + 33 task briefings are the test material for the next session: do they translate cleanly into implementation? If yes, the AI-as-documentation-engine thesis holds and this becomes Maestro's normal operating mode. If no, Epic 0 T0.1's PR will surface where the briefings need more rigor.
