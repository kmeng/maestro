## Distinctive moments

1. **MCP server reload friction.** New tools (verifier, spec_writer)
   don't appear in an in-flight Claude Code session until MCP server
   restarts. Hit twice during Epic 8: once after T8.1 (file_paths
   schema not yet active) and once before W4 Part A (spec_writer not
   visible). User restarted Claude Code's MCP connection both times.
   This is a real onboarding gotcha for shipped users — should be
   documented in v0.0.4 README / install guide.

2. **Coder hallucinates "full file" reconstructions.** T8.2 the coder
   gave technically-syntactically-valid-but-wrong rewrites of
   `models.py` / `resolve.py` — dropped existing validators, changed
   types, invented new fields. Surgical Edits saved the day. Lesson
   added to journal but not yet to memory rules: **on "return full
   file" instructions, always diff against known-good original before
   apply.** Already encoded as practice in `dispatch-protocols.md`
   "if you cannot show the file's full current content, instruct the
   coder NOT to modify regions you cannot show", but T8.2 violated
   the spirit by accepting coder's reconstruction.

3. **Plan B revised pivot (W2).** Original "B = keep RoleId unchanged"
   was infeasible because `dispatcher.run(role: RoleId, ...)` types
   the role param. Revised: widen RoleId Literal but keep the
   user-configurable `ROLE_IDS` tuple unchanged; add `SHIPPED_TOOL_IDS`
   to mark infrastructure-only tools. Result: zero team.yaml breakage,
   zero existing test fixture changes, clean conceptual split between
   "team-configurable role" (4) and "shipped dispatch identifier" (5+).

4. **T8.7 trial wave: dogfood validation success but cost ROI is in
   the future.** All 6 worker dispatches ran cleanly on first try.
   Verifier validated 10/10 claims about the spec_writer output (no
   hallucinations). New scribe schema worked. But the trial itself
   used ~26.4k worker tokens to ship a 30-line change — comparable to
   doing it by hand. **Savings will compound across future epics** as
   spec_writer replaces orchestrator-authored 5-10k-token coder specs;
   the trial bed is intentionally too-small to show that yet.

5. **Honest token accounting (self-critique).** This Epic 8 session
   itself burned more Opus tokens than baseline. Causes: (a) drafted
   long specs by hand because spec_writer wasn't shipped yet
   (chicken-and-egg), (b) verbose user-facing reports between each
   dispatch, (c) verifier on trivial cases for dogfood-completeness
   rather than necessity. Going forward: skip verifier on
   single-file <50-line obvious-pass cases; trim per-step reports;
   compress decision tables.
